# Core Beliefs

These beliefs define the intended character of the project.

## Beliefs

- Verified behaviour beats inherited confidence.
- Local control is a product feature, not just an implementation detail.
- The integration should prefer one obvious onboarding path.
- Compatibility should be documented when kept.
- Ambiguity should be treated as debt.
- Public documentation should be truthful even when the truth is incomplete.
- A small codebase should have unusually high clarity.
